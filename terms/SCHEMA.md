# 学 AI（ai-glossary）内容规范

> 本文是**内容仓的必填矩阵**：写词条前先读它。
> 机器执行方是 [`scripts/validate.mjs`](./scripts/validate.mjs)（**本文与它必须一致**；
> 改了字段或枚举，两处一起改，否则「文档说合规、校验器报错」）。
>
> 实测规模：**200 词 · 6 站**（一 35 · 二 35 · 三 35 · 四 35 · 五 30 · 六 30）+ **微型指南**（`guides/`，见 §八）。

## 一、文件位置与命名

| 项 | 规则 |
|---|---|
| 词条 | `terms/<中文名>.md` —— **一词一文件**，文件名即词条名（可含空格、连字符、点） |
| 索引 | `terms/INDEX.md` —— **手写文件**（build.mjs 只排除它、不生成它；改词条数要手动同步，2026-10-19 修正此前「构建产物」误称） |
| 英文正文 | `terms.en.json` —— 键 = 文件名去 `.md`；`_` 开头的键是元数据（`_comment` 等） |
| 生成物 | `site/data/terms.all.js` · `.baseline.terms.all.js`（后者是逐字段门禁的基准，不要手改） |

## 二、必填字段（11 个，缺一即校验失败）

| 字段 | 类型 | 说明 |
|---|---|---|
| `zh` | 字符串 | 词条名，与文件名一致 |
| `en` | 字符串 | 英文名（**不是**解释，解释在 `terms.en.json`） |
| `purpose` | 字符串 | 一句话：解决什么问题 |
| `def` | **行内数组** | 至少 1 条；每条一个完整句子。⚠ 不能写成块状数组 |
| `why` | 字符串 | 为什么需要知道（与 `purpose` 不同：一个是「是什么」，一个是「与读者何干」） |
| `refs` | 数组 | **至少 1 条**，每条**严格三段式** `["中文标签", "https://…", "English label"]` |
| `domain` | 枚举 | 见 §三 |
| `purposeTag` | 枚举 | 见 §三 |
| `level` | 整数 | 1–6，与 `layer` 一一对应 |
| `layer` | 枚举 | 一 / 二 / 三 / 四 / 五 / 六 |
| `ord` | 整数 | **层内**序号，必须 1..n 连续（页面顺序按它排） |

## 三、枚举值（封闭，不得自创）

| 字段 | 取值 | 实测分布 |
|---|---|---|
| `domain` | `concept` `model` `agent` `dev` `infra` `media` `data` `choice` | concept 56 · infra 34 · choice 33 · agent 25 · media 19 · model 14 · dev 10 · data 9 |
| `purposeTag` | `learn` `apply` `judge` `guard` | learn 80 · apply 49 · guard 36 · judge 35 |
| `layer` / `level` | `一`↔1 · `二`↔2 · `三`↔3 · `四`↔4 · `五`↔5 · `六`↔6 | 一 35 · 二 35 · 三 35 · 四 35 · 五 30 · 六 30 |

`layer` 的语义（写 `ord` 时按层排；站名与主题句的真相源是 `meta.js`，此表只是速记）：

| 层 / 站 | 主题 |
|---|---|
| 一 · 进门 | 建立直觉：AI 是什么、能做什么 |
| 二 · 上手 | 认清能力与边界：什么时候会出错 |
| 三 · 用深 | 决定好不好用的具体做法：方案靠不靠谱 |
| 四 · 看懂 | 原理：为什么会有这些表现 |
| 五 · 跑起来 | 部署：让模型跑在自己机器上 |
| 六 · 选得对 | 把学到的变成一个决定 |

## 四、可选字段

| 字段 | 类型 | 说明 |
|---|---|---|
| `alias` | 行内数组 | 别名/俗称（实测 34 个词条有）。用于检索，不显示为标题 |

## 五、双语要求（R2）

1. **frontmatter 层**：`zh` 与 `en` 都必填。
2. **正文层**：中文正文在 `.md` 里；**英文正文在 `terms.en.json`**，键与词条一一对应，
   值形如 `{"purpose": "…", "def": ["…"], "why": "…"}`。
3. 校验器要求：**每个词条都有英文键**（缺 = 错误）；有键但词条已不存在 = 警告（陈旧翻译）。
4. 中文正文的固定骨架（实测 200/200 一致，校验器检查前两项）：

```
# 词条名（English）

**解决什么问题**：{purpose}
{def 每条一段}

**为什么需要知道**：{why}

**看具体例子**：            ← 可选项（62/116 没有）
- [中文标签](url)

---
<!-- 层：第 N 层 · 一句话说明该层主题 -->
```

> ⚠ 词条正文**不用 `##` 标题**。站点页面其实是从 **frontmatter** 渲染的（`build.mjs` 不读正文），
> 正文是给在 GitHub 上直接阅读的人看的。

## 六、判定「已核验」的规则

本仓**没有** `verified` 字段 —— 判定靠 `refs`：

| 状态 | 条件 |
|---|---|
| 已核验 | `refs` 至少 1 条，且每条都是三段式、URL 指向**一手来源或本站实例页**（当前 200/200 满足） |
| 未核验 | 没有 `refs`（校验器直接判错，不允许提交） |

链接**是否可达**不在本仓校验范围内（那需要联网，属于 `_audit/refs-check.mjs` 的职责）。
写 `refs` 时遵守总则：**给出处，不给结论**；找不到一手来源就换一个更可靠的二手来源，不要编。

## 七、禁止

- ❌ 手改 `site/`、`.baseline.*`（都是产物）；`INDEX.md` 是手写文件，改词条数时记得同步它
- ❌ 自创 `domain` / `purposeTag` 值（要加先改本文 + 校验器 + 构建器的映射）
- ❌ `ord` 跳号或层内重复（会让页面顺序错乱）
- ❌ `def` 写成块状数组（`def:\n  - …`）
- ❌ `refs` 写两段式（会渲染出缺英文标签的引用）
- ❌ 词条正文里手写「共 N 词」这类计数（数字一律由构建器算）

## 八、微型指南（`guides/`，v7 S24 · 2026-10-19）

5–10 分钟一篇的操作指南（怎么提问 / 怎么验证输出 / …），以及「常见误区」子类型。
与词条同一套 frontmatter 纪律，但字段不同（指南没有 `def` / `why` / 层内全局 `ord`）。

| 项 | 规则 |
|---|---|
| 文件 | `guides/<中文名>.md` —— 一篇一文件，**文件名即 slug**（URL 身份，与词条同一规则） |
| 英文正文 | `guides.en.json` —— 键 = 文件名去 `.md`；值形如 `{"lead": "…", "points": ["…"]}`（myth 类为 `{"lead","myth","fact"}`） |
| 页面 | 构建出 `learn.specul/guide/<slug>/index.html`（HowTo / Article JSON-LD） |

必填字段（缺一即校验失败）：

| 字段 | 类型 | 说明 |
|---|---|---|
| `zh` / `en` | 字符串 | 标题，中英都必填 |
| `kind` | 枚举 | `guide`（操作指南）/ `myth`（常见误区：「大家以为…其实…」）/ `paper`（论文卡：研究问题/证据位置/作者自陈局限/它没有主张的——C5-2 起，与方法类 guide 分别计数） |
| `station` | 整数 | 1–6，挂在第几站（面包屑指回 `#layer-N`） |
| `ord` | 整数 | 按「站 × kind」分别 1..n 连续（写误区不会挪动 guide 的序号） |
| `span` | 整数 | 1–15，预计阅读分钟数 |
| `lead` | 字符串 | 一句话：这份指南解决什么 |
| `points` | 行内数组 | **guide / paper 类**：3–7 条要点（guide 渲染成 HowTo step；paper 渲染成「读这张论文要带走的」列表） |
| `myth` / `fact` | 字符串 | **myth 类**：误区原话 / 其实是怎么回事（代替 points） |
| `refs` | 数组 | **至少 1 条**，三段式，同词条口径（R5） |

可选字段：`terms`（行内数组）—— 指南依赖的词条 slug，每个必须真实存在（构建期 + 校验器双重拦截）。

正文骨架（给 GitHub 上直接阅读的人看，页面从 frontmatter 渲染）：

```
# 标题（English）

**这份指南解决什么**：{lead}

**怎么做**：            ← guide 类，points 编号成列表
1. …

**出处**：
- [中文标签](url)

---
<!-- 微型指南 · 第 N 站 · 约 M 分钟 -->
```

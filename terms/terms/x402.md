# x402（x402）

**解决什么问题**：让 API、内容或数字服务直接通过 HTTP 402 收款：客户端先拿到付款要求，付款后重试同一请求，不需要账号、API key 或订阅。

x402 复用长期保留的 HTTP 402 Payment Required 状态码：服务端在响应里给出价格、收款地址、资产与网络，客户端完成支付后带凭证重试。

它是支付协商层，不规定具体的链上结算实现；稳定币、facilitator、批量结算都可以接。

**为什么需要知道**：Agent 要按次调用大量服务，传统开户、绑卡、按月订阅都不适合机器。x402 把「这次请求要不要付、付多少、付给谁」放回 HTTP 本身，适合按次计费与微支付。

**边界**：x402 不解决退款、争议、税务和身份合规；它也不保证服务端一定履约。链上支付有波动、Gas、确认时间和私钥管理问题。对高价值交易，仍需要预算上限、白名单、人工确认与审计日志。

**怎么判断用不用**：按次调用、单价低、服务方不想开户时，x402 很合适；需要发票、退款、订阅管理或法币清算时，传统支付网关仍更完整。

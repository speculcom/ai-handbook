# 维度 1 · 模型与开放条件

> 核心问题：**用谁的模型？能不能换？**

---

## 为什么这个维度排第一

因为它是**最容易产生误解的维度**。

同一款工具可能：
- 内置一个模型，同时允许你接自己的 API Key
- 有多个模型可选，但按订阅档位限制
- 界面显示"支持 GPT-5 / Claude"，但你所在的账户只有其中之一

**"支持"这个词在产品页面里几乎没有信息量。**

---

## 要回答的四个子问题

### 1.1 支持哪些模型

| 情况 | 写法示例 |
|---|---|
| 自有模型 | `内置自有模型，不支持切换` |
| 第三方多模型 | `支持第三方模型，可自定义模型路由；具体可用模型随订阅档位变化` |
| 单模型 + 可换 | `默认接入单一模型，可配置其他厂商 API Key` |
| 不清楚 | `官方未公开模型清单；统一默认模型与全套餐映射本次未核验，记为未知` |

### 1.2 能不能接自己的 API Key

这一条决定了**长期成本可预测性**。

| 情况 | 影响 |
|---|---|
| 支持 BYOK | 成本转移到自己的账户，可控 |
| 不支持 | 只能用订阅内的额度，超出即受限 |
| 部分功能支持 BYOK | 需具体说明哪些功能 |

### 1.3 是否有分批开放

这是 2026 年之后的重要变量。

```
按账户、套餐、登录方式与客户端分批开放；
Enterprise 还需管理员启用。
模型发布不代表所有账号已经获得权限。
```

**判定**：如果官方用了「分批开放」「逐步推出」「rolling out」这类措辞，一律标为分批，不能写成"已支持"。

### 1.4 模型与订阅的关系

**必须区分三件事**：

| 关系 | 说明 |
|---|---|
| 模型能力 | 某个模型能做多难的任务 |
| 模型是否可用 | 你能不能用（看账户/套餐/地区） |
| 模型是否默认 | 新建会话默认用哪个 |

这三件事混为一谈，就会出现"我买了最高档为什么还是老模型"的困惑。

---

## 常见错误

| 错误写法 | 问题 |
|---|---|
| `支持最新旗舰模型` | 没说是否可用、是否默认 |
| `支持 Claude / GPT / Gemini` | 没说具体版本，没说是否分批 |
| `模型能力很强` | 不是这个维度要回答的 |
| 省略字段 | 无法判断是有意省略还是漏了 |

---

## 合格的写法

```markdown
model_access: >-
  支持第三方模型，可自定义模型路由；具体可用模型随订阅档位变化。
  企业版需管理员启用。**统一默认模型与全套餐映射本次未核验，记为未知。**
```

拆解：
- 说了支持什么类型（第三方多模型）
- 说了限制条件（按订阅档位、企业版需管理员）
- 说了什么没查清（映射关系）
- **没有夸大**（没说"支持全部最新模型"）

---

## 未核验时怎么写

不要猜。按这个模板：

```markdown
model_access: >-
  官方页面列出 <已确认的部分>。
  **<未核验的具体问题>，本次未核验，记为未知。**
```

同时在「未知项清单」里记一条。

# 维度 2 · 运行位置

> 核心问题：**代码在哪里跑？**

---

## 三种运行面

| 运行面 | 代码在哪 | 谁负责保持在线 |
|---|---|---|
| **本地** | 你的机器 | 你 |
| **云端沙箱** | 厂商的隔离容器 | 厂商 |
| **混合** | 部分本地 + 部分云端 | 分开看 |

**混合是最容易说不清的情况**，必须拆开写：

```
本地工程与云任务分开；
远程控制本地电脑不等于云端执行。
```

---

## 要回答的三个子问题

### 2.1 代码本体在哪里

**这是隐私问题的核心**。

| 情况 | 判定 |
|---|---|
| 全程本地，代码不出机器 | 本地 |
| 代码上传到云端索引 | 混合（索引在云） |
| 任务在云端沙箱执行 | 云端 |
| 有隐私模式 / 本地索引选项 | 写明选项存在及其代价 |

**不要假设**。很多工具"本地 IDE"形态下会把代码索引到云端做语义检索。

### 2.2 有几个入口

同一家产品常常有多个入口，运行面各不相同。

```
本地工程与云任务分开；
远程控制本地电脑不等于云端执行。
```

```
本地桌面 / IDE 与开发者 Cloud Agents 是不同运行面。
```

**判定标准**：如果官方把不同入口分开命名（IDE / CLI / Desktop / Cloud），必须分开写。

### 2.3 本地资源依赖

| 依赖 | 影响 |
|---|---|
| 需要特定 IDE 版本 | 兼容性问题 |
| 需要桌面端常驻 | 关掉就不工作 |
| 依赖本地 git 状态 | 未提交改动是否可见 |

---

## 与「关机后的任务」的关系

这两个维度必须分开。

| 运行位置 | 关机后的任务 |
|---|---|
| 回答"代码在哪" | 回答"电脑关了还能不能跑" |

**常见误解**：看到有"云端任务"入口，就推断"所有功能关机都能跑"。不成立。

---

## 常见错误

| 错误写法 | 问题 |
|---|---|
| `本地运行` | 没说索引是否上云 |
| `云端执行` | 没说代码是否离开本机 |
| `支持远程控制` | 远程控制 ≠ 云端执行，电脑还得开着 |
| `混合模式` | 太笼统，要拆开说 |

---

## 合格的写法

```markdown
runtime: >-
  本地 IDE 为主，代码索引在本机；
  远程控制本地电脑不等于云端执行。
  另有一个云端任务入口，模型与额度跟随套餐。
```

拆解：
- 主运行面说清了（本地 IDE）
- 索引位置说清了（本机）
- 明确否定了常见误解（远程控制 ≠ 云端执行）
- 补了第二个入口（云端任务）

## 「零能力」维度怎么写

**有些对象在某个维度上确实什么都不做**——
只查时间的 server 没有本地文件访问能力，
只做时间换算的工具不需要上下文记忆。

**这类维度的正确答案就是短句**：

```markdown
local_files: >-
  **无任何文件访问能力**。不涉及文件读写。

background: >-
  不支持。单次时间查询为同步操作，随客户端进程结束。

context: >-
  无状态。每次调用独立，不保留历史。
```

**不要为了凑长度而注水。**

### 三种情况的判断标准

| 情况 | 写法 |
|---|---|
| 该维度**确实为零能力** | 短句直接说，**用加粗强调零** |
| 该维度**有能力但没查清** | 必须写「本次未核验，记为未知」+ 原因 |
| 该维度**有能力且已核验** | 写清具体能力与边界 |

### 关键区别

```
✅ 无任何文件访问能力。不涉及文件读写。      ← 零能力，完整
⚠️ 文件读写能力本次未核验，记为未知。        ← 未核验，须说明
❌ 支持文件读写。                            ← 敷衍，无信息量
```

**「零能力」不是缺陷，是有效答案。**
把零能力写成未知，或为了长度虚构能力，两者都是错的。

**这条适用于全部 8 个维度。**
判断某个维度是"零能力"还是"未核验"：
看对象本身有没有这个能力，不是看这次查没查到。

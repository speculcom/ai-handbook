# 维度 4 · 关机后的任务

> 核心问题：**电脑关了，还能继续跑吗？**

---

## 这是最容易被夸大的维度

几乎所有产品都会在某个位置提到"云端任务"、"后台运行"、"异步执行"。但这些词的含义差别巨大。

---

## 三档判定

| 档位 | 判定 | 说明 |
|---|---|---|
| **真后台** | 电脑关闭、客户端退出后仍继续 | 需要厂商托管的执行环境 |
| **伪后台** | 客户端最小化可以，切到后台可以，退出就没了 | 常见形态 |
| **不支持** | 只能在当前会话里跑 | 纯本地工具 |

**关键**：不要把"有云端入口"直接等同于"所有功能能后台跑"。

```
有云任务入口；具体模型、集成与额度跟随套餐，
不能把本地会话直接当作云任务。
```

---

## 要回答的三个子问题

### 4.1 执行环境归谁

| 情况 | 含义 |
|---|---|
| 厂商托管沙箱 | 电脑关了也能跑 |
| 你自己的服务器 | 机器开着才能跑 |
| 你的本地机器 | 必须电脑开着 |

### 4.2 中断后能否恢复

| 能力 | 说明 |
|---|---|
| 可恢复 | 断线后继续，进度不丢 |
| 需手动恢复 | 要手动触发 |
| 不可恢复 | 中断即丢失 |

这一条比"能不能后台跑"更重要。**能跑但不能恢复，价值有限。**

### 4.3 额度与限制

后台任务往往有独立限额：

```
云端任务有独立并发与时长限制；
具体额度跟随套餐，本次未核验。
```

---

## 常见错误

| 错误写法 | 问题 |
|---|---|
| `支持后台运行` | 没说退出客户端后是否继续 |
| `云端执行` | 没说执行环境归谁 |
| `支持异步任务` | 太笼统，无法判断 |
| `可以关机跑` | 往往是推断，不是核验 |

**特别危险的一类错误**：把「远程控制你的电脑」写成「云端执行」。这是两个完全不同的东西——远程控制意味着电脑还得开着。

---

## 合格的写法

```markdown
background: >-
  本地任务需客户端常驻；
  另提供云端任务入口，电脑关闭后仍可继续。
  云端任务的并发数与时长限制跟随套餐，
  **完整适用范围本次未核验，记为未知。**
```

拆解：
- 明确区分本地任务和云端任务
- 说了云端能关机跑
- 说了有未知部分

---

## 未知时的写法

不要推断。写：

```
有后台任务入口；
**关机续跑的完整适用范围本次未核验，记为未知。**
```

同时进「未知项清单」。

---

## 分区路径差异

| 分区 | 现状 |
|---|---|
| IDE | 多数需要客户端常驻，云端任务能力有限 |
| CLI | 基本不支持（本来就是本地的） |
| MCP | 取决于部署方式，见 [mcp/taxonomy/transport.md](../tracks/mcp/taxonomy/transport.md) |

**CLI 分区这一维度经常是"不支持"**。这不是缺点，是形态决定的——写清楚就行，不要为了好看而含糊。

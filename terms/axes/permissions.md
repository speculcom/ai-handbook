# 维度 7 · 权限与限制

> 核心问题：**它能做什么不能做什么？数据会不会流出去？**

---

## 权限也是产品能力

不是"功能越少越安全"，也不是"功能越多越强"。

```
审批、沙箱、凭据脱敏和工具边界影响实际可用性。
OpenCode 的新修复说明可靠性不只来自模型升级。
```

**可靠性的来源不只是模型，还有权限设计。**

---

## 要回答的五个子问题

### 7.1 沙箱

| 类型 | 说明 |
|---|---|
| 无沙箱 | 命令直接在宿主机跑 |
| 文件沙箱 | 限定目录范围 |
| 容器沙箱 | 隔离进程与文件系统 |
| 双重沙箱 | 网络也隔离 |

**判定**：写清默认档位，以及能否调整。

```
沙箱与审批边界跟随运行环境。
```

这句话的意思是——**CLI 里是沙箱，桌面 app 里可能不是**。运行环境决定安全边界。

### 7.2 审批机制

| 机制 | 说明 |
|---|---|
| 每次确认 | 高安全，低效率 |
| 白名单 | 列出的操作免确认 |
| 计划模式 | 先出计划，人批一次再执行 |
| 自主执行 | 全自动，无人工介入 |

**计划模式是 2026 年的重要进步**：

```
Plan Mode 确认前不执行。
```

### 7.3 数据流向

**这是隐私的核心**。

| 要查的 | 说明 |
|---|---|
| 代码是否上云 | 索引在本地还是云端 |
| 遥测默认开还是关 | 能否关闭 |
| 是否用于训练 | 官方条款怎么写 |
| 有无企业版隔离 | 企业数据是否不参与训练 |

**判定标准**：以官方隐私政策与条款为准，不推测。

### 7.4 计费边界

**这一条经常被忽略，但很贵。**

```
本地与云端共用订阅用量，可能另有周限额。
API key 计费与订阅不是同一额度。
```

```
付费额度跨聊天、Code 与工作任务共享；
滚动 5 小时与周限额按账户执行。
```

| 要写清 | 为什么 |
|---|---|
| 多个功能是否共用额度池 | 影响实际可用量 |
| 限额是累计还是滚动 | 滚动窗口撞限等于停工 |
| API 是否独立计费 | 很多人以为订阅含 API |
| 加购额度是否过期 | 过期即浪费 |

### 7.5 第三方凭据

```
调试凭据脱敏
```

如果工具会接触密钥、token、配置文件，要写清：
- 默认是否脱敏
- 日志是否记录敏感内容
- 有无专门的凭据管理

---

## 常见错误

| 错误写法 | 问题 |
|---|---|
| `安全可靠` | 空洞，且无法核验 |
| `权限控制完善` | 具体做了什么？ |
| `数据不上传` | 绝对化，通常有例外 |
| 忽略计费边界 | 用户会踩坑 |

---

## 合格的写法

```markdown
permissions: >-
  沙箱与审批边界跟随运行环境；CLI 默认目录沙箱，
  桌面端策略可能不同。遥测可关闭。
  **本地与云端共用订阅用量，API key 单独计费。**
  企业数据是否用于训练，以官方条款为准，
  **本次未逐条核验，记为未知。**
```

拆解：
- 说明了权限随环境变（重要）
- 给出了具体默认值
- 计费边界写清了
- 隐私条款明确说"以官方为准 + 未核验"

## 安全提示

本维度的记录**不构成安全评估**。

它只记录**官方声称的机制**和**可核验的默认值**。
真实安全性取决于你的配置和具体环境。

如果某工具有明显风险，在这里点出来：

```
默认请求全文件系统访问权限；
如需收紧要手动配置目录白名单。
```

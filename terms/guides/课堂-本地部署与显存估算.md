# 课堂教案：本地部署与显存估算（Lesson - Local Deployment and VRAM Estimation）

**这份教案解决什么**：学员按权重、KV 缓存、运行时开销三项列估算表，再用运行器的占用输出核对，分清能启动、跑得动、答得完三个问题。

**课时目标**：
- 能把显存需求拆成权重、KV 缓存与运行时开销，并说明每项随什么变化。
- 能用参数量与量化位宽做权重量级的算术估算，并标明这是估算。
- 能读懂运行器占用输出，判断是否发生 CPU 与 GPU 混合加载。
- 能给出装不下时的三条备选路径，并说明各自代价。

**材料**：
- llama.cpp 官方 README：1.5 到 8-bit 整数量化，以及 CPU＋GPU 混合推理。
- Ollama 官方 FAQ：ollama ps 的 PROCESSOR 列与 num_ctx 上下文设置。
- Hugging Face Transformers 官方 KV 缓存文档（仓库源文件）：缓存占用、卸载与量化缓存。
- 一张估算表：参数量、位宽、上下文长度、批量、可用显存、可用内存。

**步骤**（15 分钟微课）：
1. 3 分钟算权重：用参数量乘每参数字节数，写明位宽假设与算式。
2. 4 分钟加缓存与开销：标出随上下文长度和批量变化的项，留出余量。
3. 4 分钟核对占用：读官方文档里的示例输出，判断加载位置与是否需要卸载。
4. 4 分钟给备选：更小规格、更低量化档、部分卸载各写一条代价与下一步实测条件。

**常见误解**：
- 以为权重装得下就跑得快；缓存与卸载会改变速度和延迟。
- 以为量化只省显存；官方文档把它写成内存与速度的取舍，质量要在自己任务上核对。
- 以为本地部署就等于数据合规；还要看日志、权限与出网路径。
- 把文档示例里的占用数字当成自己机器的结果；硬件与设置不同。

**评分核对**：
- 估算表三项齐全，每项写明假设与来源，算式可复核。
- 能区分估算与实测，并说出下一步实测要固定哪些条件。
- 备选路径带代价，不写「最好」，也不承诺具体速度数字。

**出处**：量化位宽与混合推理的口径取自 llama.cpp 官方 README。它写明支持 1.5 至 8-bit 整数量化，并支持 CPU＋GPU 混合推理以加速超过显存容量的模型。

占用输出的读法取自 Ollama 官方 FAQ。PROCESSOR 列会显示全部在 GPU、全部在系统内存，或两者的比例。

缓存部分取自 Transformers 官方文档。KV 缓存可占显著内存，长上下文生成时成为瓶颈。文档给出卸载与量化缓存两条省空间的做法，并提示它们与延迟之间有取舍。

# 系统提示怎么设计（How to Design a System Prompt）

**这份指南解决什么**：系统提示是产品行为的隐形规格书。这篇讲写什么、不写什么、怎么测它有没有生效。

**怎么做**：
1. 只放长期规则：身份、语气、边界、拒答口径；一次性任务放用户消息，别混进系统提示。
2. 写成可检查的条款：「引用外部信息必须给链接」比「要诚实」可执行，也便于逐条测试。
3. 边界条款要给出路：拒绝时说明原因并给替代方案，只写「不能做」会得到生硬拒答。
4. 系统提示不是安全边界：足够用心的用户总能绕开，真正的防线在权限与工具侧。
5. 逐条写测试：每条规则配一个「应触发/不应触发」的输入，改一版跑一遍。
6. 版本与配对同提示词管理：系统提示改动也要配模型版本记录和回归。

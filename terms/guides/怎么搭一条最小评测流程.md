# 怎么搭一条最小评测流程（How to Set Up a Minimal Evaluation Pipeline）

**这份指南解决什么**：不必攒几十项基准。一条能用的评测流水线只要五件东西：样本、口径、判法、记录、复跑。

**怎么做**：
1. 样本从自己的工作里挑 20–50 条，记下来源与场景，比抄一份公开基准更贴近你的用法；留出一部分不参与改提示，专门用来看改动前后。
2. 口径写成人能直接判的问题：不是「这条回答好不好」，而是「它有没有把材料里没写的期限当成依据」。
3. 判法分两层：机器能判的（字段是否齐、引用编号是否真的存在）先跑脚本；判不了的留人工，并记下人工判了多大比例。
4. 记录要能复盘：模型版本、提示版本、样本集版本、日期、每条的对错与理由，缺哪一格，下次就没法跟这一轮比。
5. 换掉任何一环都用同一套样本复跑；同一输入跑两三遍看波动，波动本身也是记录。
6. 举个例子（虚构数据）：输入是 30 条「合同条款问答」样本 → 处理是脚本查引用编号是否存在、人工判断结论是否与条款一致 → 结果判断是这一批 24/30 条通过（虚构计数，不是实测结果）→ 下一步先看错的是引用缺失还是判断偏差：前者改检索与提示，后者改验收口径，别一起动。
7. 样本会老：用户问法变了、政策文本换了，就补新样本并重标一部分旧样本，否则流程还在跑、量的是过去。

**出处**：评测流水线与持续样本的思路参考官方评测文档、HELM 论文与持续数据流评测研究；例子中的样本数与通过数是虚构数据。

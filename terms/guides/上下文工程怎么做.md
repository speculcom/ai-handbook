# 上下文工程怎么做（How to Do Context Engineering）

**这份指南解决什么**：上下文工程不是「多塞资料」，而是决定每一轮该让模型看到什么、看不到什么，以及怎么压缩。

**怎么做**：
1. 先定必放项：当前目标、硬约束、可用工具、输出格式、一两个示例；其余都是可选项。
2. 删掉无关历史与重复工具输出：同一份文件读三次，只保留最新一次与差异。
3. 压缩用摘要或结构化状态：把长对话压成「已确认事实 / 待办 / 未决问题」，而不是逐字截断。
4. 工具输出要治理：分页、截断、只取相关段落，并保留来源引用，避免把整页塞进上下文。
5. 给记忆划边界：会话内状态、跨会话事实、外部检索三层分开，不要把检索结果当记忆。
6. 验收看两件事：任务成功率是否上升、每轮 token 是否下降；两者都变好才算有效。

**出处**：上下文分层与压缩策略参考 Anthropic 官方文章；长上下文中段利用问题见 Lost in the Middle；跨会话状态见 LangGraph Persistence。

七件事是核对清单Seven checks, not an installer

这七件事是本地跑的核对清单，不是安装教程。

清单是：可用容量、驻留体积、文件与运行器、缓存口径、许可、结果验收、日志落点。

顺序从「能不能装下」走到「结果算不算数」。某一条查不下去就先停，不要靠改配置碰运气。

本站不下载权重、不代跑模型，也不给某台机器能不能跑的结论。

These seven items are a pre-run checklist, not an installation tutorial.

The list is: available capacity, resident size, file and runner support, cache scope, licence, output acceptance, and where logs go.

The order runs from "will it fit" to "does the result count". Stop at the first item you cannot verify instead of changing settings blindly.

This site downloads no weights, runs no models, and draws no conclusion about whether a particular machine works.

逐条怎么查How to check each one

每条给三行内容：查什么、拿什么当证据、查不过去时下一步。证据一律回到官方页与本机读数。

  • 可用容量：查当前任务真能用多少，不查设备标称总量。证据是系统占用与运行器分配。
  • 驻留体积：查加载后实际占多少，不只看下载文件多大。证据是启动后的占用读数。
  • 文件与运行器：查该架构、该任务、该版本有没有明确支持说明。缺说明就保留未知。
  • 缓存口径：先确认架构是不是同层标准全注意力，再决定能不能套 KV 算式。
  • 许可：查发布页给的许可标识与条款入口，本站不替读者判断某个用途。
  • 结果验收：先写任务、输入、判定标准和失败处理，再跑第一次生成。
  • 日志落点：查日志写到哪、谁有权限读、留多久，另见日志那一篇。

Each item has three parts: what to check, what counts as evidence, and the next step when the check fails. Evidence always returns to official pages and readings taken on your own machine.

  • Available capacity: check what this task can actually use, not the device's advertised total. Evidence is system usage plus runner allocation.
  • Resident size: check what the loaded model occupies, not only the download file size. Evidence is the reading after startup.
  • File and runner: look for an explicit support statement covering this architecture, task and version. Absent a statement, keep it unknown.
  • Cache scope: first establish whether the decoder is standard same-layer full attention, then decide whether the KV formula applies at all.
  • Licence: read the licence identifier and terms link on the publishing page; this site does not judge a specific use case.
  • Output acceptance: write the task, inputs, pass criteria and failure handling before the first generation.
  • Log location: check where logs are written, who may read them and how long they stay; see the local-logs guide.

可用容量与驻留体积Available capacity and resident size

设备标称总量不等于任务可用量。驱动、系统界面、其他进程和运行器自己都在同一块内存里排队。

硬件规格页给的是型号口径，不是某个任务的可用读数。本站没有核对过任何具体机器。

十进制 GB 与 GiB 是两个单位。1 GiB 是 1,073,741,824 字节，同一条算式里不要混着写。

驻留体积是加载后的占用，不等于仓库文件体积。转换精度、张量布局和运行器分配都会改它。

  • 查不过去时：先关掉同机的其他占用，再用短输入起一次，记录读数后才加上下文长度。

Advertised device capacity is not task-available memory. Drivers, the desktop, other processes and the runner itself all queue in the same memory.

Hardware specification pages give published SKU figures, not a reading for your task. This site checked no specific machine and reports no available figure.

Decimal GB and GiB are different units. One GiB is 1,073,741,824 bytes; do not mix the two inside one calculation.

Resident size is loaded occupancy, not repository file size. Precision conversion, tensor layout and runtime allocation all change it.

  • If the check fails: release other local load first, start with a short input, record the reading, and only then increase context length.

文件与运行器：格式存在不等于支持The file and the runner: a format is not support

本地跑的前提是运行器认得这个模型。格式要求、后端开关和支持清单都写在运行器文档里。

运行前提与下载方式见 llama.cpp 官方文档：docs/models.md，后端编译开关见 docs/build.md。

  • 架构支持：查运行器有没有列出该架构，从哪个版本开始列。
  • 任务接口：对话、嵌入、识别是不同入口，换个任务不等于换个文件。
  • 多模态：图像与音频的接入件常是独立文件，缺它只会退回文字路径的行为。
  • 版本差异：同一模型在不同运行器版本上的能力可能不同，未列出的保留未知。

A local run requires the runner to recognise the model. Format requirements, backend switches and the support list are all in the runner documentation.

Run prerequisites and download syntax appear in the official llama.cpp documentation: docs/models.md; backend build switches appear in docs/build.md.

  • Architecture support: check whether the runner lists this architecture and from which release.
  • Task contract: chat, embedding and recognition are separate entry points; changing the task is not merely changing the file.
  • Multimodal: the image/audio attachment is often a separate file; without it you fall back to text-only behaviour.
  • Version drift: the same model can differ across runner versions; anything not listed stays unknown.

缓存口径：公式只管同层全注意力Cache scope: same-layer full attention only

KV 缓存算式是 2 × L × Hkv × D × B × C × N。字节结果除以 1,073,741,824 才是 GiB。

它只在标准全注意力 MHA / GQA 解码器上成立。前提是各层结构相同，且每层都保留完整键值。

MLA、混合状态空间、滑动窗口和逐层结构不同的缓存都不在这个范围内，硬套会算错。

L、Hkv、D 从模型配置取，B 从运行器配置取。架构确认不了就选「未确认」，不要用参数量倒推。

字段与算式在容量工作台上逐项填写：上下文与并发预算。

它给的是假设下的占用估计，不能据此承诺跑得起来、不超时，也不承诺输出质量。

The KV cache formula is 2 × L × Hkv × D × B × C × N. Divide the byte result by 1,073,741,824 to obtain GiB.

It holds only for standard full-attention MHA/GQA decoders whose layers share the same structure and keep complete key/value state per layer.

MLA, hybrid state-space designs, sliding windows and per-layer differing caches are outside that range; forcing the formula onto them produces wrong numbers.

Take L, Hkv and D from the model configuration and B from the runner configuration. If the architecture cannot be confirmed, select "unconfirmed" rather than back-solving from parameter count.

Fill the fields and see the arithmetic in the capacity workbench: context and concurrency budget.

It estimates occupancy under your assumptions. It cannot promise that a run starts, that it stays within a time limit, or that output quality is acceptable.

许可与用途：以发布页为准Licence and use: take the publishing page

许可标识、条款入口和用途限制都写在发布页。本站逐条抄标识，不解读、不总结、不改写。

  • 标识为非宽松类（other、cc-by-* 一类）时，先读条款再决定用途。
  • 第三方量化仓通常注明继承基础模型的许可，产物本身的发布者另算。
  • 官方未说明的用途问题保留未说明，不用社区说法补成一个答案。

Licence identifiers, terms links and use restrictions live on the publishing page. This site copies the identifiers item by item and neither interprets, summarises nor rewrites the terms.

  • When the identifier is non-permissive (other, cc-by-* and similar), read the terms before deciding on a use.
  • Third-party quantisation repositories usually note inheritance from the base model; the publisher of the quantised artefact is a separate matter.
  • Where the official page is silent about a use case, it stays recorded as not stated; do not substitute community claims for an answer.

结果验收与日志落点Output acceptance and where logs go

第一次生成之前先写下任务、输入、判定标准和失败处理。验收看预先写好的判定，不看单次观感。

结果检查从这几处进入：本地运行完整流程、20 项自测清单、按症状排查。

费用构成用这个入口记录：成本计算器。它算的是任务口径下的成本，不预测某台机器的表现。

日志落在哪、谁能读、留多久是另一件事，见「把日志留在本地到底意味着什么」。

Before the first generation, write down the task, inputs, pass criteria and failure handling. Acceptance follows the criteria written in advance, not a single impression.

Entry points for checking results: the local-model workflow, the 20-item self-test and troubleshooting by symptom.

Record cost components with the cost calculator. It works on task terms and does not predict a specific machine.

Where logs land, who may read them and how long they persist is a separate question; see "What keeping logs local actually means".

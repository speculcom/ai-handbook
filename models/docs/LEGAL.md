# 法律与合规

> 本站的法律立场只有一句：**只索引、只引述、不托管、不解读、不给意见。**
> 下面每一条都是可执行的约束，不是免责声明模板。

## 五原则

### 1. 只索引
本站展示的是**元数据索引**——模型名、许可、体积、档位、下载量、发布页链接。
所有元数据来自 Hugging Face 公开 API，不含任何我们自己创作的内容（除了明确标注为「我们的口径」的判断）。

### 2. 只引述
所有事实性描述都是**转述**发布页上的公开信息，并给出原文链接。
我们不复制发布页的长段原文（README 全文等），只引用必要字段与短句。

### 3. 不托管
**本站不下载、不存储、不分发任何模型权重文件。**
页面上出现的所有 `.gguf` 文件名与体积都是**元数据**，点击后跳转到 Hugging Face 发布页，
由发布者自己托管分发。这条是规避「再分发」法律风险的核心设计。

### 4. 不解读许可
我们**不解释**许可条款意味着什么、能不能商用、适不适合你的场景。
我们只做两件事：
- 原样显示 `cardData.license` 字段值
- 提供发布页的许可原文链接，并提示「以发布页原文为准」

对于 `other`、`cc-by-*`、`gpl`、`openrail` 等非宽松许可，页面显著位置标注需要自行核对原文。

### 5. 不给法律意见
本站内容不构成法律建议。
`legal.html` 里有完整免责声明，与本页一并适用。

## 商标

本站提及的模型名称（如 Qwen、Gemma、GLM、Llama、Mistral、DeepSeek、Kimi、MiniCPM 等）
均为其各自权利人的商标，此处仅作**描述性使用**——指明所讨论的对象是谁。
本站与上述任何厂商无隶属、代理或合作关系。

## 量化产物的许可

一个量化版 GGUF 通常涉及**两层许可**：

| 层 | 许可来源 | 本站如何呈现 |
|---|---|---|
| 基础模型权重 | 原模型发布方的许可 | 独立显示，来自官方仓 `cardData.license` |
| 量化产物 | 量化者在其发布页声明的许可 | 独立显示，来自量化仓 `cardData.license` |

如两层许可不同，页面会分别标注。我们**不判断**二者如何组合——那需要法律判断。

## 数据采集的合规性

- 全部来自 Hugging Face 公开只读 API，无鉴权、无绕过
- 遇 gated 仓库（401/403，需登录授权）：**跳过并记录，不尝试绕过**
- 采集频率：手动触发，不做高频抓取
- 请求间隔 ≥ 900ms，尊重服务端限流

## 已知风险与我们的处置

| 风险 | 处置 |
|---|---|
| 量化权重许可与基础模型不一致 | 两层许可分别显示，不合并、不推断 |
| `other` 许可含义不明 | 标为「须读发布页原文」，给原文链接 |
| 第三方量化质量不可控 | 不做质量断言；量化者档案只描述「做了什么」，不评价「好不好」 |
| 商标误用 | 仅描述性使用，页脚声明无隶属关系 |
| 数据陈旧 | 每页标注采集时间，视为快照 |

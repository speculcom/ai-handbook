## [怎么用这页|How to use]

模板内的比例、样本数、阈值和权限策略是示例。请按任务、授权与风险确定实际条件；填完表格不等于已经通过验收。

四张表用于评审会与上线前检查；复制到你的仓库，按项目填。

### 1. 项目立项检查表

```text
- [ ] 目标一句话：要解决谁的什么问题
- [ ] 不做清单：明确不做什么
- [ ] 数据来源与许可：能否使用、能否留存
- [ ] 模型与工具：主选、备选、许可证
- [ ] 成本上限：月调用/硬件/人力
- [ ] 验收指标：三条可量化
- [ ] 失败回滚：谁负责、怎么退
- [ ] 时间盒：到哪天必须评审
```

### 2. 内容发布前检查表

```text
- [ ] 事实：每条结论有来源与日期
- [ ] 引文：单条不超过 100 字符或一句
- [ ] 权利：图片/音乐/字体/数字人许可已登记
- [ ] 隐私：无客户姓名、订单号、密钥
- [ ] 标注：需要 AI 生成标注的平台已标注
- [ ] 版本：模型版本与生成参数已存档
- [ ] 可访问性：字幕、对比度、替代文本
- [ ] 回滚：发布后 24 小时内可撤
```

## [常见误用|Common misuses]

- 目标之外也要写明不做什么，避免范围含糊。
- 发布表只查事实：不查权利，最容易返工。
- 单条迁移样本不足以覆盖多种任务，应按实际范围补充。
- 泄露表只填一半：第三方子处理者最常被漏。

## [已填示例：内部资料问答的立项记录|Filled example: an internal document-Q&A project]

这是虚构项目，用来演示如何填写，不是产品推荐或已完成部署。

| 字段 | 已填内容 |
|---|---|
| 目标 | 从已批准的内部说明中回答报销问题，并标出依据段落 |
| 范围 | 不接生产系统，不修改订单，不替员工审批 |
| 数据 | 先用虚构政策与问题；真实文档另核权限与使用范围 |
| 工具约束 | 只能读取指定资料；不能执行材料中的指令 |
| 验收 | 答案有依据；规则例外不漏；无答案时明确说明 |
| 失败处理 | 引用不支持答案时停止发布该回答，保留问题与证据记录 |
| 成本 | 分别记录输入、输出、检索、重试和维护；单价由负责人填当前来源 |

验收问题至少覆盖正常报销、例外条款和资料中没有答案三类。样本数量按任务范围确定，不能因为表格已填满就判断项目可以上线。

接着使用本页的泄露路径表，逐项记录应用、模型接口、日志与备份分别保存什么。

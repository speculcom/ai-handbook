# CLI 形态实测协议

CLI 形态的实测协议与 IDE 形态**共用基础协议**，两条形态的差异见下表，
CLI 形态另有三个特有测试维度（第二至四节）。

> ⚠ 基础协议原文档（旧路径 `ide/tasks/_protocol.md`）在 v4 三分区合并后**已不存在**
> （2026-10-09 核验：`tracks/agents/tasks/` 下只有本文件一份协议）。
> 本行此前指向一个已消失的路径 —— 记录为内容缺口，不假装基础协议仍可点开。

## 一 · 与 IDE 协议的差异

| 维度 | IDE 形态 | CLI 形态 |
|---|---|---|
| 基础协议 | ✅ 共用 | ✅ 共用 |
| 环境记录 | 硬件/系统 | 硬件/系统 + **shell** |
| 判定标准 | 通过/部分/失败 | 同上 |
| **非交互模式** | — | **新增，见第二节** |
| **CI 环境** | — | **新增，见第三节** |
| Git 集成深度 | — | **新增，见第四节** |

## 二 · 非交互模式测试（CLI 特有）

**这是 CLI 形态最重要的测试**，因为它决定能不能进 CI。

### 测试方法

对每个工具，跑一次：

```bash
<tool> --print "把 src/index.ts 里的常量 DEFAULT_TIMEOUT 改成 5000"
```

（或该工具的等价单次执行命令）

### 记录项

| 记录项 | 说明 |
|---|---|
| 是否有单次执行模式 | 没有就记「不支持」 |
| 输出是否可控 | 纯文本 / JSON / 可解析 |
| 退出码语义 | 成功 0？失败非 0？ |
| 能否管道使用 | 输出能否直接进下一个命令 |

### 判定

| 档位 | 标准 |
|---|---|
| **可用** | 完整任务 + 结构化输出 + 正确退出码 |
| **勉强** | 能完成但输出混杂日志，需二次解析 |
| **不可用** | 无单次模式，或退出码不可靠 |

## 三 · CI 环境测试（CLI 特有）

**很多 CLI 工具在无 TTY 环境下会挂。**

### 测试环境

```bash
# 无 TTY 环境模拟
env -i PATH=/usr/bin:/bin HOME=/tmp/ci <tool> --print "..."
```

### 记录项

| 记录项 | 说明 |
|---|---|
| 无 TTY 是否正常 | 是 / 否 / 报错信息 |
| 是否需要配置文件 | 默认配置在无家目录时是否可行 |
| 是否需要交互确认 | 审批提示会卡住吗 |
| 能否容器化 | 是否依赖系统特有组件 |

### 判定

| 档位 | 标准 |
|---|---|
| **CI 友好** | 无 TTY 可运行，无需交互 |
| **需配置** | 加参数或环境变量后可跑 |
| **CI 不友好** | 必须有 TTY 或必然卡在交互 |

## 四 · Git 集成深度（CLI 特有）

| 级别 | 说明 | 测试方法 |
|---|---|---|
| **L0 无** | 纯文件操作 | 改完后看 `git status` 是否干净 |
| **L1 只读** | 能看 diff，不能提交 | 让它解释一次变更 |
| **L2 可提交** | 能 commit | 让它改完直接提交 |
| **L3 完整** | 分支 / PR / 变基 | 让它开分支改完合回 |

### 记录

```markdown
| 工具 | Git 级别 | 说明 |
|---|---|---|
| Aider | L3 | 自动 commit，可配分支策略 |
| OpenCode | L2 | 可提交，分支需手动 |
| XXX | L0 | 只改文件，git 需手工处理 |
```

**L0 不算缺陷**——有些工具刻意不做 Git 操作。要写清是设计选择还是能力缺失。

## 五 · 环境记录补充

CLI 形态的环境记录要加：

```markdown
## 测试环境（CLI 补充）
- shell：<bash 5.2 / zsh / fish>
- 终端复用：<是否用 tmux>
- PATH 配置：<工具如何加入 PATH>
- Provider 配置方式：<环境变量 / 配置文件 / 交互式登录>
- 依赖版本：<node / python / go 版本要求>
```

**「Provider 配置方式」尤其重要**。有些工具靠交互式登录存凭据。这在 CI 里跑不了。

## 七 · 本轮局限必须包含

CLI 形态特有的局限要额外写：

```markdown
- 仅测试了 Unix shell，未覆盖 Windows 环境
- 未测试各工具的付费额度上限
- Provider 数量测试不完整，只接了 <N> 家
```

**特别是 Windows**。很多 CLI 工具在 Windows 上有已知问题。不写清楚会误导 Windows 用户。

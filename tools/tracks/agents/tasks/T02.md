# T02 · 缺陷修复（跨文件）

**形态**：CLI（同形态适用于 IDE）

**基线仓库**：`atlas-bench-fixture` @ `bench-baseline`（commit `5db3db6`）

**前置**：出题人必须先植入一个有明确症状的 bug。**植入的 commit 与位置要记录**（见下方「任务准备」）。否则无法判定「工具是否引入回归」。

---

## 任务准备（出题人先做，P1 第 2 项）

在 atlas-bench-fixture 的 `bench-baseline` 之上植入一个真实 bug。**它的症状要分散在多个文件**：

- 选一处，不超过 3 个文件
- 建议在 `physics` 模块改一个常数（如重力系数），让 `game` 模块的调用方仍用旧假设
- 症状：`npm test` 失败，但报错信息指向无关文件（迫使工具追根因）

> ⚠ **必须 commit 这个 bug 状态并打独立 tag**（如 `atlas-t02-bug`），记录：
> - 改了哪几个文件、哪一行
> - 改前的正确值 / 改后的错误值
> - 预期报错信息
>
> 实测从 `atlas-t02-bug` 这个 commit 开始，工具负责修复回到绿色。

---

## 任务描述（植入 bug 后，可直接喂给任意工具）

```
atlas-bench-fixture 的测试现在失败了（在 atlas-t02-bug 状态下）。
定位并修复根因，使 npm run typecheck 与 npm test 全部通过。
只能改必要文件，不要为了过测试而改测试本身。
```

---

## 验收标准

| 判定 | 条件 |
|---|---|
| **通过** | 定位到正确的根因文件（不是只改表象）、typecheck 过、test 全绿 |
| **部分通过** | 症状消失但改法影响其他模块，或修好了但引入了新问题 |
| **失败** | 未修复，或修复后仍有测试失败，或改动超出 3 个文件 |

---

## 关键观察点

- 工具是**定位根因**还是**绕过症状**（改测试让它过 = 失败）
- 是否检查了其他调用点（同一常数是否还有别处引用）
- diff 是否超出 3 个文件

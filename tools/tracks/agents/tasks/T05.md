**前置**：出题人需先制造一个**依赖或配置层面的问题**（见下方「任务准备」）。不要制造纯语法错误。

---

## 任务准备（出题人先做，P1 第 2 项）

在 `bench-baseline` 上制造一个构建层面的真实问题，例如：
- `package.json` 的脚本错误（如 `build` 脚本拼错、漏掉步骤）
- `tsconfig` 的路径配置问题（如 `include` / `paths` 写错导致某目录不被编译）
- 不制造纯语法错误（那是 T03 的范畴）

> ⚠ **必须 commit 这个坏构建状态并打独立 tag**（如 `bench-t05-broken`），记录改了什么、预期 `npm run build` 如何失败。
> 实测从 `bench-t05-broken` 开始，工具负责让 `npm run build` 恢复成功。

---

## 任务描述（制造问题后，可直接喂给任意工具）

```
atlas-bench-fixture 现在 npm run build 跑不通（在 bench-t05-broken 状态下）。
定位并修复构建配置问题，使 npm run build 成功通过。
不要靠删检查项或加跳过参数来蒙混过关。
```

---

## 验收标准

| 判定 | 条件 |
|---|---|
| **通过** | `npm run build` 成功，且没有绕过检查（不加 `--force`、不删 `typecheck`） |
| **部分通过** | build 成功但削弱了检查（如删掉 `tsc --noEmit` 才过） |
| **失败** | build 仍失败，或用了跳过检查的手段 |

---

## 特别检查（判部分通过的关键依据）

diff 里有没有删掉 `tsc --noEmit`、或给 build 命令加 `--force`：
- 有 → 「削弱检查过关」，判**部分通过**

---

## 关键观察点

- 是否定位到配置/依赖层根因，还是乱试命令
- 是否理解 `tsc --noEmit && vite build` 这条构建链（atlas-bench-fixture 构建依赖 Playwright + Chromium）

# MCP 特有维度 C · 权限范围

> 核心问题：**这个 server 能碰到多少东西？能改吗？**

---

## 这是 MCP 分区最重要的维度

一个 IDE 权限大一点，用户还能忍——它本来就要读写你的代码。

**一个 MCP server 权限失控，是直接的供应链风险。**

所以这个维度的判定必须**明确**，不能含糊。

---

## 三层范围

### 第一层 · 文件系统范围

| 档位 | 说明 |
|---|---|
| 整个文件系统 | 能读写任意路径 |
| 用户主目录 | 限制在 `~` |
| **配置白名单** | 只能访问启动参数指定的目录 |
| 当前工作目录 | 仅 cwd |
| 只读指定路径 | 可读不可写 |

**关键**：写清是"默认行为"还是"配置后行为"。

```
默认限制在启动时指定的目录；
未指定则继承客户端工作目录。
```

### 第二层 · 操作类型

| 档位 | 说明 |
|---|---|
| 只读 | 只能读 |
| 可写 | 能创建/修改 |
| **可执行** | 能运行命令 ⚠ |
| 可删除 | 能删 |

**可执行和可删除是最高风险的两档**，必须在正文里明确警告。

### 第三层 · 领域特定能力

| 类型 | 例子 |
|---|---|
| 版本控制写操作 | `git push` / 创建 PR |
| 数据库写操作 | `UPDATE` / `DELETE` |
| 外部 API 调用 | 发消息、创建工单 |
| 网络请求 | 任意 URL 抓取 |

**这一层常被忽略**。比如 postgres server 如果默认只读，和默认可写，风险完全不同。

---

## 默认值 vs 可配置值

**必须区分**：

| 情况 | 写法 |
|---|---|
| 默认窄，可放宽 | `默认只读；可通过参数放开写权限` |
| 默认宽，需收紧 | ⚠ `默认请求全盘访问；如需收紧要手动配置白名单` |
| 固定窄 | `仅支持只读，无参数可放开` |

**默认宽的是重点风险对象**，必须在 `pitfalls` 里写一条。

---

## 常见误解

| 误解 | 真相 |
|---|---|
| 「本地运行所以很安全」 | 本地意味着权限等于你的用户权限，可能是管理员 |
| 「stdio 没有认证所以没风险」 | 无认证 ≠ 无边界，边界就是文件权限 |
| 「官方 servers repo 里的应该都安全」 | 官方仓库同样需要审查权限范围 |
| 「只读就绝对安全」 | 只读仍可泄露 `.env`、SSH key、数据库配置 |

**第四条最重要**：只读 server 能读到你的所有敏感配置。

---

## 组合风险

**单个 server 权限合理，叠加后可能失控。**

| 组合 | 风险 |
|---|---|
| 3 个只读 server | 低 |
| 只读 + 写文件 + 可执行命令 | 高 |
| 涉及凭据的多个 server | 高 |
| 网络可达 + 可执行 | 极高 |

**建议在条目里写清组合建议**：

```
建议与只读类 server 搭配；
不建议与可执行命令类 server 同时启用。
```

---

## 判定要点

### ① 文件范围（默认 vs 可配）

```
默认限制在启动参数指定的目录；
未指定时继承客户端工作目录。
```

### ② 操作类型（明确警告可执行/可删除）

```
提供读文件、写文件、建目录工具；
**不提供删除与命令执行**。
```

**如果提供命令执行，必须在这里写清楚**：
```
提供执行任意命令的工具，
可访问范围与客户端用户权限相同。⚠
```

### ③ 领域能力

```
提供 SQL 查询与执行工具；
**是否默认只读取决于连接的数据库角色**。
```

### ④ 可否收紧

```
支持通过参数限制目录白名单。
```

---

## 常见错误

| 错误写法 | 问题 |
|---|---|
| `权限可控` | 没说默认是什么 |
| `安全性良好` | 主观，无法判定 |
| `可配置权限` | 没说配置范围多大 |
| 省略 | 最危险 |

---

## 合格写法

```yaml
mcp:
  scope: >-
    文件访问默认限制在启动参数指定的目录，
    未指定时继承客户端工作目录；不支持访问目录之外。
    提供读文件、写文件、建目录、移动文件工具；
    **不提供删除与命令执行**。
    无独立审批机制。
```

拆解：
- 默认范围说清了
- 可收紧说清了（不支持访问外）
- 工具列表列清了
- **明确否定了删除和命令执行**
- 审批机制说明

---

## 安全提示

**本维度的记录不构成安全评估。**

真实风险取决于：
- 你如何配置这个 server
- 客户端进程本身的权限级别
- 同一台机器上还有什么东西能访问相同资源

**如果本条目显示权限很宽，不要据此认为你的部署不安全**——
关键是把它收紧，或者放到容器里跑。

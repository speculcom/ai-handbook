# T03 · 类型迁移（跨文件，TypeScript 专项）

**形态**：CLI（同形态适用于 IDE）

**基线仓库**：`atlas-bench-fixture` @ `bench-baseline`（commit `5db3db6`）

**为什么值得做**：TypeScript 的跨文件迁移是最容易暴露工具水平的地方。只改定义处、漏掉调用点，会直接 typecheck 报错。工具若不确定可空性，就会加错误的 `!` / `as any` 逃逸。

---

## 任务描述（示例形态，可直接喂给任意工具）

```
把 src/net/ 下的某个 X API 从 A 形式迁移到 B 形式（具体 A/B 由出题人在出题时给定，
确保是全仓库有 ≥3 个调用点的真实 API）。
找出所有调用点并全部更新，保证 npm run typecheck 零错误、npm test 全绿。
```

> 出题人需在任务里明确「从什么形式到什么形式」，且确认调用点 ≥ 3 个，避免任务过窄。
> 若 `src/net/` 当前形态不适合，可改选另一个跨文件使用的模块，但必须记录选中了哪个。

---

## 验收标准

| 判定 | 条件 |
|---|---|
| **通过** | 全部调用点更新、typecheck 零错误、test 全绿、无 `as any` / 多余 `!` 逃逸 |
| **部分通过** | typecheck 过但用了类型逃逸（`any` / `!` / `@ts-ignore`） |
| **失败** | 漏掉调用点导致 typecheck 错误，或测试失败 |

---

## 特别检查（判部分通过的关键依据）

diff 里有没有 `as any`、`!` 非空断言、`@ts-ignore`：
- 有 → 算**部分通过**（靠压制类型系统过关，不是真正修好）
- 无 → 才可能算**通过**

---

## 关键观察点

- 是否用 `grep` / 类型报错逐一定位所有调用点，还是只改了定义处
- 是否理解可空性（加了正确的 nullable 处理，而非一律 `!`）

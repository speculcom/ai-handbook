# T01 · 仓库上手与验收标准列举

**形态**：CLI（同形态适用于 IDE）
**基线仓库**：`atlas-bench-fixture`（JSDoc 类型 + 纯 JS，零运行时依赖）
**基线 commit**：`bench-baseline`（tag → commit `5db3db6`）

> 原基线是 KEEL 3D 项目的私有快照基线。因该项目已废弃（2026-09-29 从零重启、与旧版完全无关），基线更换为独立仓库 `atlas-bench-fixture` @ `bench-baseline`。该仓库专为实测设计：零运行时依赖，含 JSDoc 类型检查 + 12 个测试 + 配方注册表 + 可复现性能热点，四项验证（typecheck / test / catalog:check / build）在基线状态下全绿。

**验证命令**：
- `npm run typecheck`（`tsc --noEmit`）
- `npm test`（基线断言数请先跑 `npm test` 确认；T01 验收以「全绿」为准，不硬卡具体数字）

**每轮重置**：`git checkout bench-baseline && git clean -fdx && npm install`

## 任务描述（原文，可直接喂给任意工具）

```
先阅读 atlas-bench-fixture 的 README 与 package.json，列出这个项目的验证方式
（typecheck / test / build 分别跑什么）。
然后在 src/recipes/ 下新增一个 recipe 条目，注册到 catalog，
使 npm run catalog:check 与 npm test 全部通过。

不要修改任何既有文件，只新增。
```

---

## 验收标准

| 判定 | 条件 |
|---|---|
| **通过** | `npm run typecheck` 零错误；`npm test` 全绿；diff 只含新增文件 |
| **部分通过** | typecheck 过但 test 有失败，或修改了既有文件但功能正确 |
| **失败** | typecheck 有错误，或 test 失败，或未完成注册 |

---

## 关键观察点

- **工具是否主动跑验证命令**（最关键）——很多工具改完不会自动 `typecheck` / `npm test`
- 是否先读 README / package.json 再动手，而不是凭猜测建文件
- 是否理解 catalog 注册机制（而非把文件乱放、导致 `catalog:check` 不过）

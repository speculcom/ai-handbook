## 四种贡献

### 1 · 新增对象

适合「这个工具还没被收录」。

**步骤**：

1. 确认对象符合赛道的收录标准（见 `tracks/<track>/_track.md`）
2. 复制同赛道任意条目作为模板
3. 按 [axes/](./axes/) 填 8 个维度，**抓不到就写「未知」**
4. 准备至少 2 条官方源，**必须含 changelog 和 docs**
5. 提 PR

**不要做的事**：
- 不要为了填满字段而推测
- 不要加池外标签
- 不要给未核验的信息编数字

### 2 · 修正错误

适合「这条数据错了或过期了」。

**PR 必须包含**：
- 哪个条目 + 哪个字段
- 现在写的什么
- 应该是什么
- **你的依据链接**（官方源）

不接受无来源的修正。

### 3 · 补充未知项

适合「这个未知项我查到了」。

**最欢迎的贡献类型。** 把你查到的东西补上，并在 PR 里说明你是怎么查的（看了哪个页面、哪一段）。

### 4 · 补充实测

适合「我跑了任务，有记录」。

**步骤**：
1. 读本赛道 `tasks/_protocol.md`
2. 按协议跑
3. 记录到 `runs/<date>-r<N>.md`

**必须包含**：
- 测试环境（硬件、系统、日期）
- 失败案例
- 局限说明

**只记成功的实测不收。**

## 硬性规则

违反这些的 PR 会被退回：

| # | 规则 |
|:--:|---|
| 1 | 8 个维度字段必须齐全，未知写「未知」+ 原因 |
| 2 | `sources` 至少 2 条，必须含 `kind: changelog` |
| 3 | `pitfalls` 至少 1 条，且必须是具体误解 |
| 4 | `last_verified` 是**你核验官方源的日子**，不是官方发布日 |
| 5 | 不采不存价格数字与档位报价（D9）；「多少钱」只放官方定价页链接 |
| 6 | 不得给单一总分排名 |
| 7 | 有邀请关系必须用 `link.kind: invitation` 并填写 `incentive` |
| 8 | 不在仓库里放 HTML/CSS/JS |
| 9 | `related` 至少 1 条，且必须指向**另一分区**（守卫：`_audit/link-graph.mjs`） |

## 标签规范

从固定池取（见 [SCHEMA.md 标签池](./SCHEMA.md#六标签池)）。

需要新标签时，在 PR 里说明为什么现有标签不够用。**不要新建同义标签**（比如已有 `编程` 就不要再造 `开发`）。

## 跨分区条目

**两级概念先分清**（完整说明见 [SCHEMA.md §2.5.1](./SCHEMA.md#251-两级命名分区-vs-形态容易混先读这条)）：

- **分区**（3 个，由目录决定）：`agents` / `harness` / `tools`
- **形态**（5 个，由 frontmatter `track:` 决定）：`ide` / `cli` / `cloud` / `harness` / `mcp`

`ide` / `cli` / `cloud` 三种形态都落在 `agents` 分区。

**约定**：
- **一个形态一个文件**，都在本分区目录下
- 文件名带形态后缀：`claude-code.md`（`track: ide`）/ `claude-code-cli.md`（`track: cli`）
- **`id` 必须全仓库唯一**（构建期硬失败）
- 跨分区互链写 frontmatter **`related`**（至少 1 条，只装**另一分区**的 id）；
  同分区对照写正文 `## 相关条目`，两条分工见 [SCHEMA.md §2.5.2](./SCHEMA.md#252-related-与正文相关条目的分工)
- 跨分区引用另一个档案时，路径用**当前目录名**：`../../harness/products/x.md` ✅ / `../../cli/products/x.md` ❌（旧名，仓里不存在）
- **不要复制粘贴同一段数据**——重复的两处会不一致，构建时会被检出

**改完必须跑**：
```bash
node scripts/validate.mjs            # 0 错 0 警
node scripts/completeness.mjs        # 不降
node ../../_audit/link-graph.mjs     # 双口径 100%
```

## Commit 信息

```
<type>: <简述>

type:
  add       新增对象
  fix       修正数据
  doc       改文档/方法论
  test      补充实测
  meta      仓库配置
```

示例：
```
add: cursor — AI 编程 IDE

补充 Cursor 的 8 维度档案。
档位能力差异已核到官方定价页；报价数字按 D9 口径不存。
证据：changelog + docs + pricing 三个官方源，核验日 2026-09-28。
```

## 方法论修改

改 [METHODOLOGY.md](./METHODOLOGY.md) 比改数据更需要证据。PR 里必须说明：

1. **为什么现有规则不够用**（给具体案例，不是假想场景）
2. **新规则如何避免旧规则的问题**
3. **从哪个版本生效**
4. **是否需要回溯修订历史数据**

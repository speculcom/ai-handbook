# 维度 6 · 上下文与记忆

> 核心问题：**它记得多少？断了能接上吗？**

---

## 把"上下文"和"记忆"分开

这两个词经常混用，但差别很大：

| 概念 | 含义 | 生命周期 |
|---|---|---|
| **上下文** | 当前会话里模型能看到的内容 | 单次会话 |
| **记忆** | 跨会话保留的信息 | 多会话 |
| **索引** | 对代码库的语义检索结构 | 跨会话（但不是"记忆"） |

**"它能记住"这句话，在不同产品里可能指三件完全不同的事。**

---

## 要回答的四个子问题

### 6.1 索引算法与范围

```
跨文件索引 + 会话恢复；
跨项目记忆的具体边界未知。
```

要写清：
- 索引了什么（当前项目 / 全部项目 / 只索引打开的文件）
- 什么进索引（代码 / 文档 / 依赖 / 配置文件）
- 索引是本地还是云端（见 [维度 2](./runtime.md)）

### 6.2 上下文窗口与压缩策略

| 策略 | 说明 |
|---|---|
| 简单截断 | 超出就丢最早的 |
| 摘要压缩 | 压缩历史，保留大意 |
| 外部化 | 关键信息存文件，按需读取 |
| 分层 | 保留最近 + 摘要旧内容 |

**重要提醒**：**上下文压缩不等于可靠长期运行**。

```
计划、工作记录、环境检查与明确交接，让新会话接得住旧进度；
仅做上下文压缩不等于可靠长期运行。
```

压缩会丢信息。真正的长期运行靠**状态持久化 + 显式交接**。

### 6.3 会话恢复

| 能力 | 说明 |
|---|---|
| 可恢复 | 断线/关掉后继续，进度不丢 |
| 可分叉 | 从某一步分出多条分支试错 |
| 有检查点 | 能回到任意历史状态 |

### 6.4 跨会话记忆边界

这一条最容易夸大。

**必须区分**：
- 官方**声称**能记住什么
- 实际能检索到什么
- 用户能不能要求遗忘

```
官方称可保留偏好、持续推进目标，
并允许用户要求忘记指定内容。
```

写「官方称」而不是当成事实——这是必要的限定。

---

## 常见错误

| 错误写法 | 问题 |
|---|---|
| `上下文强大` | 无信息量 |
| `支持长期记忆` | 什么叫长期？跨会话还是跨月？ |
| `不会丢失上下文` | 绝对化，通常不成立 |
| 把索引说成记忆 | 混淆两个概念 |

---

## 合格的写法

```markdown
context: >-
  对当前工作区建立跨文件索引，本地执行；
  会话可恢复与分叉。上下文超限时以摘要压缩。
  **跨项目记忆的具体边界本次未核验，记为未知。**
```

拆解：
- 索引范围说清了（当前工作区）
- 索引位置说清了（本地）
- 恢复能力说清了（可恢复可分叉）
- 压缩策略说清了（摘要）
- 不知道的标出来

---

## 评测这条维度的实用方法

如果要做实测，建议测这三件事：

| 测试 | 方法 | 观察 |
|---|---|---|
| 会话恢复 | 跑一个长任务，中断，重开 | 进度保住了吗 |
| 长任务一致性 | 同一任务跑到 50 轮对话 | 中途有没有丢失约束 |
| 大仓库检索 | 问一个跨 10+ 文件的问题 | 能不能找到正确位置 |

第三个尤其能区分工具——很多工具在小文件上表现很好，一到跨模块就崩。

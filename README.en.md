# AI Quantized LLM Atlas

> 中文版：[README.md](./README.md)

> **An atlas of quantized models you can run locally** — it answers exactly one question:
> for this base model, which quantized version should I download, and why?
>
> Live: https://models.specul.com/
> Deploy repo: https://github.com/speculcom/models

## What this is

An **index**, not a review site.

- We read model metadata from the public Hugging Face API (license, size, architecture,
  context length, quantization tiers)
- We shape it into **tables you can compare horizontally**, with a source on every number
- **We run no benchmarks and state no conclusion about which model is stronger**

## What this is not

- ❌ Not a review site (no capability comparisons)
- ❌ Not a weight mirror (**we do not download or host any model files**)
- ❌ Not a news site (no hot takes, no news)

## How to read this

10 base models, 132 quant variants, 1253 GGUF files. Nobody reads that list top to
bottom, so don't. Start from where you are:

| Where you are | What to do |
|---|---|
| "Will this run on my machine?" | Pick from the **series table** below; member and variant counts are there, file sizes live in `data/series/*.json` |
| "Why is this variant downloaded so much?" | Read the quantizer profiles in [`data/quantizers/`](./data/quantizers/) — the same model quantized by different people differs a lot |
| "Should I use this model at all?" | Read [`docs/selection-*.json`](./docs/): why these were chosen, and the process is traceable |
| "Why is there no Q4_K_M?" | The naming rules section of [`docs/METHODOLOGY.md`](./docs/METHODOLOGY.md) |

One line to keep in mind: this repo answers **"which file do I download, and why"**.
It does not answer "which model is stronger".

Live version: <https://models.specul.com/>

## Common commands

```bash
# ① Collect (note hf-mirror rate limits; serial with a 900ms gap; runtime grows with
#   the number of series — see Measured size at the end)
node scripts/collect-models.mjs

# ② Post-process: re-apply the tier-naming rules (**this step is mandatory**)
#    Newly collected data mixes in ~210 non-weight files (mmproj / tokenizer / imatrix …).
#    Skipping it makes the page suggest "download 非权重文件（0.0 GB，未识别）", and
#    models-check reports "unrecognized". It also recomputes coverage / totalGB / recommended.
node scripts/fix-quants.mjs

# ③ Backfill licenses for quant variants (**this step is mandatory**)
#    Most HF quantization repos simply have no license field in the model card
#    (bartowski / AtomicChat / AesSedai …). This is not a collection failure —
#    quantization is a mathematical transform of the weights, so the license must be
#    inherited from the base model.
#    The script writes licenseInherited + licenseFrom as a trace, and the page labels
#    the entry "inherited from base".
node scripts/backfill-license.mjs

# ④ Audit (exits 1 and blocks the build if rules are violated)
node scripts/audit-licenses.mjs

# ⑤ Build the site
node scripts/build.mjs
```

> ⚠ **Steps ②③ were missing from this file** (caught twice on 2026-10-09 while writing up
> A6.5: jumping straight to the audit first failed with "quant variant missing license",
> and after backfilling, "unrecognized" showed up on the page).
> **Neither step can be skipped between collection and audit.**

## Changing the series list

1. Edit the `SERIES` array in `config.js`
2. **Sync both translation files** (otherwise English mode shows Chinese and the build
   warns about missing keys)
   - `summaries.en.json` — key = `<seriesCode>`
   - `member-notes.en.json` — key = `<seriesCode>|<repo name>`
3. Re-run `collect-models.mjs`
4. Run `fix-quants.mjs` (drops non-weight files; see the warning above)
5. Run `backfill-license.mjs` (see the warning above)
6. Run `audit-licenses.mjs` to confirm compliance
7. Run `build.mjs`
8. **Sync the cross-site counts**: `_data/glossary/terms/参数.md` ("N series, M specs") and
   the badge on `www.specul/index.html` — both are watched by the "www hub" / learn guards
   in `_audit/content-freshness.mjs`, and drift there gets reported
9. Deploy

**Do not hand-edit `data/series/*.json`** — it is script output and will be overwritten
on the next collection.

## Traps hit while collecting

| Trap | Symptom | Fix |
|---|---|---|
| **hf-mirror rate limiting fails silently** | Non-200 responses look like 404s | Serial requests, fixed 900ms gap, exponential backoff |
| **Search returns the wrong model** | Searching `DeepSeek-V4-Flash` returns `Qwen3.5-9B-DeepSeek-V4-Flash` | Hard filter: repo name minus GGUF must **equal** the model id |
| **Fine-tune derivative repos flood results** | abliterated / uncensored / Distilled have huge download counts and top the charts | A `DERIVED` regex excludes them; those are re-releases, not quantizations |
| **`cardData.base_model` is unreliable** | Official GGUF repos often lack the field | Don't anchor on it; match repo names strictly |
| **Official GGUF repo not searchable** | `openbmb/MiniCPM5-2B-GGUF` is missing from the index | Probe the `<org>/<Model>-GGUF` naming convention directly |
| **bash quoting breaks node scripts** | `!==` inside `node -e` gets eaten by the shell | Always write a `.mjs` file |

## Legal position

**Index and quote only. Do not host, do not interpret licenses, do not give legal advice.**

See [`docs/LEGAL.md`](docs/LEGAL.md). The short version: we organize public metadata and
label sources; whether a weight is worth downloading, where from, and whether you may use
it commercially is between you and its publisher.

## Data accuracy tiers

| Tier | Meaning | Page label |
|---|---|---|
| **A · objective fact** | Read directly from the API | ✅ measured field |
| **B · derived** | Computed from A by a published rule | ✅ derived |
| **C · our judgement** | Our own reading | ❌ our reading |

**We do not write tier-C content without labelling it.** Claims about which model is better
or faster need benchmarks, and this site makes none.

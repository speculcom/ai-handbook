Aider

Aider-AI / aider

终端里的结对编程 agent，直接读写本地 git 仓库、生成 diff、自动提交，并用 repo map 控制上下文。A pair-programming agent in the terminal that reads and writes a local git repo, produces diffs, commits automatically and uses a repo map to control context.

50.2k stars 5177 forks Python 语言Language Apache-2.0 许可License 最近推送Last push 2026-05-22

为什么选Why choose it

  • 最小侵入的 coding agent 基线：一个命令、一个仓库，每轮改动都能用 git diff 审。Git-native: every change is a diff you can review and revert.
  • Repo map、edit format 和自动 lint/test 回环的设计，值得做代码 agent 的人拆开看。The repo map keeps context focused on relevant files.
  • 支持多家模型和本地端点，方便横向比较模型在真实仓库上的编辑能力。Works well for small, well-scoped edits.

不适合Not for

需要图形 IDE、多 agent 并行或大规模团队权限管理的场景。You need an autonomous agent that runs long multi-step tasks.
没有 git 的目录，或不允许 agent 直接改文件的仓库。The repository is too large or noisy to map usefully.

最小上手Minimum setup

  1. pip install aider-chat，准备 git 仓库和模型 API key。Run it on a clean branch with a one-file task.
  2. 在干净分支上让 aider 改一个 README 或小函数，检查 diff。Review the diff and the commit message before accepting.
  3. 开一个测试命令，让它改代码后自动跑测试，观察失败重试。Test a task that touches two files and check the repo map context.

依赖与成本Dependencies and cost

Python 3.10+；git；模型 API 或本地端点；可选 lint/test 命令。Check runtime, model weights and external service dependencies in the README.

许可与使用边界License and usage boundaries

代码 Apache-2.0；模型与数据另计。Code is Apache-2.0; model weights, training data and generated content may have separate terms — check each before commercial use.

开源不等于可商用：GPL / AGPL 有传染性；代码许可、模型许可、生成内容许可要分开看。上线前读仓库 LICENSE 与模型卡，必要时让法务确认。Open source is not automatically commercial-use friendly: GPL / AGPL are copyleft; code, model and output licenses are separate. Read the LICENSE and model card before launch, and involve legal when needed.

  • Codex CLI — 生产可用Production，OpenAI 的本地 coding agent：Rust 实现、OS 级沙箱、MCP 与云任务交接，适合终端里改代码。OpenAI’s local coding agent: Rust binary, OS-level sandbox, MCP and cloud-task handoff, built for editing code in the terminal.
  • OpenCode — 生产可用Production，终端里的开源 coding agent：build / plan 双 agent、LSP 反馈、75+ 模型提供商，另有桌面 beta。An open-source coding agent in the terminal: separate build and plan agents, LSP feedback, 75+ model providers and a desktop beta.

下一步Next steps

  • 打开 GitHub，先读 README、LICENSE、最近 release 与 issue。Open GitHub and read the README, LICENSE, latest release and issues first.
  • 按“部署依赖 / 显存 / 数据 / 网络 / 权限”列一张上手清单。Make an onboarding checklist for deployment dependencies, VRAM, data, network and permissions.
  • 用一个小样本跑通，再决定是否进生产；不要直接上生产数据。Run a small sample first, then decide on production; never start with production data.

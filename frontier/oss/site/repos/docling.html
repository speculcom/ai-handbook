Docling

docling-project / docling

文档解析工具包：PDF / HTML / Office 转结构化 Markdown / JSON，保留版面、表格与阅读顺序。

70.8k stars 5384 forks Python 语言 MIT 许可 最近推送 2026-11-18

为什么选

  • 版面、表格与阅读顺序处理比简单 PDF 抽取更完整。
  • 可本地跑，适合私有文档与内网 RAG。
  • 输出结构清楚，便于接 chunk / 索引管线。

不适合

只需要纯文本、不关心版面的场景，用更轻的抽取器即可。
扫描件质量极差时，仍要 OCR 与人工校对。

最小上手

  1. 装包后跑一个 PDF → Markdown 示例，检查标题层级与表格。
  2. 换一份含合并单元格/扫描页的文档，记录失败页。
  3. 把输出接进自己的 chunk 管线，抽 20 个 chunk 看引用。

依赖与成本

Python 3.9+；CPU 可跑基础解析；OCR/版面模型与大批量任务建议 GPU。

许可与使用边界

代码 MIT；文档内容版权归原作者，解析输出不改变原文档许可。

开源不等于可商用：GPL / AGPL 有传染性；代码许可、模型许可、生成内容许可要分开看。上线前读仓库 LICENSE 与模型卡，必要时让法务确认。

替代与相邻

  • Unstructured — 生产可用，文档 ETL 工具：把 PDF、HTML、图片、Office 文件分区、清洗并带上元数据，喂给 RAG。
  • Marker — 特定场景，PDF → Markdown / JSON 的高质量转换器，重点处理版面、表格、公式与阅读顺序。
  • RAGFlow — 先试这个，带文档解析、切分、检索与引用的 RAG 平台，适合把一套知识库跑起来。

下一步

  • 打开 GitHub，先读 README、LICENSE、最近 release 与 issue。
  • 按“部署依赖 / 显存 / 数据 / 网络 / 权限”列一张上手清单。
  • 用一个小样本跑通，再决定是否进生产；不要直接上生产数据。

Evidently

evidentlyai / evidently

数据与模型监控框架：数据漂移、质量、LLM 输出评测都能出报表、测试与带告警的看板。A data and model monitoring framework: drift, quality and LLM output checks with reports, tests and alerting dashboards.

8.1k stars 977 forks Jupyter Notebook 语言Language Apache-2.0 许可License 最近推送Last push 2026-09-29

为什么选Why choose it

  • 传统 ML 的数据漂移与 LLM 文本指标在同一套报告里。Data drift and model quality live in one report.
  • Preset 与测试套件成熟，适合上线前基线、上线后回归。Tests can run in batch or production.
  • 可自托管看板，数据不必全送第三方。Alerting turns monitoring into an operational loop.

不适合Not for

不是 agent 轨迹级评测平台，复杂多步任务要看 TruLens/Langfuse。You need only offline evaluation with no production monitoring.
指标多不等于都对，阈值要按业务校准。You have no reference dataset for drift comparison.

最小上手Minimum setup

  1. pip 装 evidently，用官方 demo 数据生成一份报告，先看指标定义。Compare a current batch with a reference batch.
  2. 换自己的 100–200 条样本，建立上线前基线。Add one quality test and one drift test.
  3. 把关键指标做成定期任务，接告警而不是只存报表。Send a failing report to a test channel before enabling alerts.

依赖与成本Dependencies and cost

Python + 数据/模型输出；看板要服务与存储。LLM 评测还要模型 API 或本地推理。Check runtime, model weights and external service dependencies in the README.

许可与使用边界License and usage boundaries

代码 Apache-2.0；数据与模型另算。Code is Apache-2.0; model weights, training data and generated content may have separate terms — check each before commercial use.

开源不等于可商用：GPL / AGPL 有传染性；代码许可、模型许可、生成内容许可要分开看。上线前读仓库 LICENSE 与模型卡，必要时让法务确认。Open source is not automatically commercial-use friendly: GPL / AGPL are copyleft; code, model and output licenses are separate. Read the LICENSE and model card before launch, and involve legal when needed.

  • Arize Phoenix — 生产可用Production，开源 LLM 追踪与评测平台，基于 OpenTelemetry，带可视化与数据集管理。Open-source LLM tracing and evaluation on OpenTelemetry, with visual exploration and dataset management.
  • TruLens — 生产可用Production，LLM 应用与 agent 的评测、追踪工具，基于 OpenTelemetry，把检索、生成与评分串成可解释的 trace。Evaluation and tracing for LLM apps and agents on OpenTelemetry, connecting retrieval, generation and feedback into an explainable trace.

下一步Next steps

  • 打开 GitHub，先读 README、LICENSE、最近 release 与 issue。Open GitHub and read the README, LICENSE, latest release and issues first.
  • 按“部署依赖 / 显存 / 数据 / 网络 / 权限”列一张上手清单。Make an onboarding checklist for deployment dependencies, VRAM, data, network and permissions.
  • 用一个小样本跑通，再决定是否进生产；不要直接上生产数据。Run a small sample first, then decide on production; never start with production data.

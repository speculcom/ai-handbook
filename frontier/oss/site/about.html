OSS · About

收录方法

这个站回答一个问题：这个仓库能不能拿下来、读得懂、跑得动、改得动。它不回答“哪个最强”。

收什么

公开 GitHub 仓库，AI 相关，有明确用途，能读、能改、能自建。优先收有文档、有许可、最近一年有维护的仓库。首批 50 个：6 个场景各 6 个精选，另 14 个目录补充。

不收什么

不收只有宣传页没有代码的；不收无许可或许可不清的；不收长期归档且没有替代价值的（除非作为历史对照）；不收纯模型权重（权重在 模型站）；不收商业 SaaS（服务在 工具站）。

字段与口径

stars / forks / language / license / pushed_at 来自 GitHub API 2026-11-19 快照；之后的变化没有回写。许可以仓库 LICENSE 为准；标签与“适合 / 不适合”是编辑判断，不是 GitHub 元数据。

不排名、不背书

不按 star 排序，不生成总分，不写“最强 / 最安全”。开源仓库的代码、脚本、模型权重都可能带来安全与许可风险；本站只做索引与风险提示，不审计代码，也不替你做法律判断。

和工具站怎么分

工具站写“别人帮你跑的服务怎么用”：价格、权限、能力、限制。OSS 写“你自己拿下来跑”：许可、活跃度、依赖、上手成本、能不能改。同一个项目可以两站各一张卡，但正文不复制，互相链一次。

纠错

发现许可、链接、快照字段有误，走 纠错页；写清仓库、字段、证据链接与核验日。

Agent 经济的五层：
账户、身份、支付、卡网络、x402Five layers under the agent economy:
accounts, identity, payments, card networks, x402

ERC-4337 解决「不改共识层也能自定义账户」；ERC-8004 解决「陌生 Agent 凭什么被信任」；AP2 解决「Agent 代付的授权证据」；Visa TAP 与 Mastercard Agent Pay 把卡组织的真实交易跑通；Algorand x402 把原子与赞助交易接进机器支付。前三条状态完全不同：成熟标准、Draft、生产未确认；卡网络已 live，但不能替代 AP2 的 mandate 层。ERC-4337 handles custom accounts without consensus changes; ERC-8004 handles why an unknown agent is trusted; AP2 handles authorisation evidence for agent payments; Visa TAP and Mastercard Agent Pay run real card-network transactions; Algorand x402 adds atomic and sponsored transactions to machine payments. The first three have very different status — a mature standard, a Draft and unconfirmed production — while card networks are live but do not replace AP2’s mandate layer.

把「已上线 / Draft / 生产未确认 / 卡网络 live / 技术接入」分开写，是本页最重要的口径。不要把「有规范」写成「已普及」，也不要把「卡网络已跑通」写成「AP2 已落地」。Separating live / Draft / unconfirmed-production / card-network-live / technical-integration is the point of this page. Do not write “has a spec” as “widely used”, or “card networks are live” as “AP2 is deployed”.

2026-11-23协议 / 支付Protocol / payments

Algorand x402：原子交易 + 赞助交易Algorand x402: atomic and sponsored transactions

Algorand 把 x402 的支持从 2 月的技术接入推进到原子交易与赞助交易：多个动作可作为一组交易同时成功或同时失败；facilitator / 服务方可以代付网络费，实现 gasless 支付流。x402 用 CAIP-2 标识网络，Algorand 主网 USDC 为默认资产之一。Algorand has extended its x402 support from the February technical integration to atomic and sponsored transactions: multiple actions settle together or fail together; a facilitator or service can cover network fees for gasless payment flows. x402 uses CAIP-2 network identifiers, with Algorand mainnet USDC among the default assets.

为什么值得看Why it matters

Agent 支付的难点不是「能付」，而是「付款、授权与用量记录要么一起成立、要么一起回滚」。Algorand 的原生原子分组把这三步压进一个结算单元；赞助交易则让没有 ALGO 的 Agent 也能先付款。对做按次 API、MCP 付费工具与机器对机器结算的人，这是 x402 多链化里值得看的一步。The hard part of agent payments is not “can pay” but making payment, authorisation and usage accounting either all hold or all roll back. Algorand’s native atomic grouping puts them into one settlement unit; sponsored transactions let an agent without ALGO pay first. For pay-per-call APIs, paid MCP tools and M2M settlement, it is a notable step in x402’s multi-chain expansion.

边界 / 它没主张什么Boundary / what it does not claim

原子分组是 Algorand 账本能力，不是 x402 新增的跨链标准；赞助交易仍由 facilitator 承担信用与合规风险。官方页面没有披露真实交易量、失败率或商户数，2026-11-23 的报道是二手来源。它没主张「x402 已在 Algorand 大规模生产」或「原子交易消除支付纠纷」。Atomic grouping is an Algorand ledger capability, not a new cross-chain x402 standard; sponsored transactions still leave credit and compliance risk with the facilitator. Official pages disclose no live volume, failure rate or merchant count, and the 2026-11-23 report is secondary. It does not claim x402 is at large-scale production on Algorand, or that atomic transactions eliminate payment disputes.

为什么值得看Why it matters

它把「Agent 代付」的授权范围写成可验证的 mandate，而不是传一张卡号；对做 Agent 结账、订阅与争议处理的团队，这是必须理解的协议层。It writes the scope of agent payment authorisation into verifiable mandates instead of passing a card number; for agent checkout, subscriptions and disputes, it is a required protocol layer.

It does not claim scale, or unconditional agent charging.

为什么值得看Why it matters

它把「陌生 Agent 凭什么被信任」拆成可查询的三层，而不是一句「上链即可信」。对做 Agent 市场、跨组织委派与支付的人，这是 2026 年最值得先读的协议。It splits “why trust an unknown agent” into three queryable layers instead of “on-chain means trust”. For agent marketplaces, cross-org delegation and payments, it is the first 2026 protocol to read.

It does not claim every agent must register, or that registration equals trust.

2025-10协议 / 卡组织Protocol / card networks

Visa TAP + Mastercard Agent Pay：卡组织把 Agent 支付跑进真实商户Visa TAP + Mastercard Agent Pay: card networks put agent payments into live merchants

Visa 2025-10-14 发布 TAP，用 Web Bot Auth 的 HTTP 签名让商户区分「浏览」与「支付」，2026-07 在欧洲 30+ 发卡行与 lastminute.com 等商户跑通；2026-10 BILL + Billtrust 用 TAP 完成 B2B 发票支付 pilot。Mastercard Agent Pay 用 KYA 注册、每个 agent 独立 Agentic Token、Payment Passkeys 与 Verifiable Intent，2025 美国上线，2026 在新加坡、亚太与拉美多市场 live。Visa released TAP on 14 October 2025: Web Bot Auth HTTP signatures let merchants distinguish browsing from paying, with live European purchases across 30+ issuers and merchants such as lastminute.com in July 2026, and a BILL + Billtrust B2B invoice-payment pilot in October 2026. Mastercard Agent Pay combines KYA registration, a unique Agentic Token per agent, Payment Passkeys and Verifiable Intent; it launched in the US in 2025 and went live across Singapore, Asia-Pacific and Latin America in 2026.

为什么值得看Why it matters

补上链站缺的一层：Agent 支付不只在链上，卡组织已经用签名、token 与生物识别把真实交易跑通。对照 AP2 的 mandate 层，能看清谁在做授权、谁在做结算、谁只是规范。It fills a missing layer: agent payments are not only on-chain. Card networks already run real transactions with signatures, tokens and biometrics. Compared with AP2’s mandate layer, it shows who authorises, who settles and who only has a spec.

边界 / 它没主张什么Boundary / what it does not claim

TAP 与 Agent Pay 不是同一标准，也不能互相替代；它们依赖卡网络与发卡行，退款、争议与拒付仍在既有卡规则里。AP2 截至 2026-10 仍没有公开确认的生产交易；把「卡网络已 live」写成「AP2 已普及」是混层。TAP and Agent Pay are different standards and cannot substitute for each other; they depend on card networks and issuers, and refunds, disputes and chargebacks stay under existing card rules. AP2 still has no publicly confirmed production transaction as of October 2026; writing “card networks are live” as “AP2 is everywhere” conflates layers.

2021-09协议 / 账户抽象Protocol / account abstraction

ERC-4337：不改共识层的账户抽象ERC-4337: account abstraction without consensus changes

UserOperation + 独立 mempool + Bundler + EntryPoint + Paymaster；用户意图不进共识层，也能做自定义签名、批量操作与代付 gas。UserOperation + a separate mempool + Bundler + EntryPoint + Paymaster; custom signatures, batching and sponsored gas without touching the consensus layer.

为什么值得看Why it matters

它是「Agent 钱包」与「代付」绕不开的底座；理解 alt mempool 与 Paymaster，才能判断一个 Agent 支付方案是真的链上执行，还是只做了一个托管账户。It is the base that “agent wallets” and sponsorship cannot avoid; understanding the alt mempool and Paymaster is how you tell real on-chain execution from a custodial account.

边界 / 它没主张什么Boundary / what it does not claim

alt mempool 带来 bundler 中心化与审查风险；Paymaster 赞助可被滥用；不同 EntryPoint 版本兼容性要单独确认；不改共识层也意味着底层仍是 EOA + 合约。它没主张「保证 gasless」或「唯一 AA 路线」。The alt mempool brings bundler centralisation and censorship risk; Paymaster sponsorship can be abused; EntryPoint versions need separate compatibility checks; avoiding consensus changes leaves EOA + contract underneath. It does not claim guaranteed gasless transactions or the only AA route.

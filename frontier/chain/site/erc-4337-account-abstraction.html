协议档案Protocol records

ERC-4337：账户抽象（alt mempool）ERC-4337: account abstraction (alt mempool)

问题：普通 EOA 的验证规则写死在协议里，智能合约钱包想自定义签名、批量操作、代付 gas，就得改共识层。ERC-4337 用 alt mempool + EntryPoint 绕开共识层，把「用户意图」变成 UserOperation。
证据位置：EIP 摘要给出 UserOperation、独立 mempool、bundler 打包与 handleOps 调用；官方文档把角色拆成 EntryPoint、Bundler、Paymaster，并说明 Paymaster 可代付 gas / 用 ERC-20 付费。
局限：alt mempool 带来 bundler 的中心化与审查风险；Paymaster 赞助可被滥用，需要声誉/限额策略；它不改共识层，也意味着底层账户模型仍是 EOA + 合约；不同 EntryPoint 版本（v0.6/0.7/0.8）兼容性要单独确认。
它没主张的：不是 EIP-7702 的替代；不保证 gasless（只是把付费方换成 Paymaster）；不是唯一的账户抽象路线；不是「所有钱包都已支持」。Problem: an EOA’s validation rules are fixed by the protocol; a smart-contract wallet that wants custom signatures, batching or sponsored gas would need consensus changes. ERC-4337 avoids that with an alt mempool and an EntryPoint, turning user intent into a UserOperation.
Where the evidence sits: the EIP abstract defines UserOperation, a separate mempool, bundler packaging and the handleOps call; the official docs split roles into EntryPoint, Bundler and Paymaster, and note that a Paymaster can sponsor gas or accept ERC-20.
Limits: the alt mempool brings bundler centralisation and censorship risk; Paymaster sponsorship can be abused without reputation/limits; avoiding consensus changes leaves the base account model as EOA plus contract; EntryPoint versions (v0.6/0.7/0.8) need separate compatibility checks.
What it does not claim: a replacement for EIP-7702; a guarantee of gasless transactions (it moves who pays); the only account-abstraction route; that every wallet supports it.

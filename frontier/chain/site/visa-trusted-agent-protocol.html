支付与结算Payments & settlement

Visa TAP：让商家认出可信的购物 AgentVisa TAP: letting merchants recognise trusted shopping agents

交集：TAP 解决“商家怎么确认这个 agent 真是消费者授权的，而不是恶意 bot”。它在 Web Bot Auth 的 HTTP Message Signatures 上加支付语义：签名请求能区分 browse 与 pay、绑定背后的消费者账户、声明期望的支付方式（网络 token、guest checkout 或 micropayment）。
适用范围：Visa 与 Cloudflare 共创，2025-10-14 在 Visa Developer Center 与 GitHub 开放；Adyen、Ant International、Checkout.com、Coinbase、CyberSource、Elavon、Fiserv、Microsoft、Nuvei、Shopify、Stripe、Worldpay 参与反馈。2026 已进入真实交易：Visa Intelligent Commerce 在欧洲 30+ 发卡行与 lastminute.com 等商户跑通；BILL 与 Billtrust 用 TAP 完成 B2B 发票支付的 live pilot。
未解决：TAP 不是链上协议，也不定义退款/争议责任；商户要接签名验证与目录，agent 要注册并被发卡/网络认可；跨网络互操作靠 Web Bot Auth，覆盖仍在扩张。The intersection: TAP answers “how does a merchant know this agent is really consumer-authorised, not a malicious bot?” It adds payment semantics on top of Web Bot Auth HTTP Message Signatures: a signed request can distinguish browse from pay, bind the consumer behind the agent, and declare the expected payment method (network token, guest checkout or micropayment).
Scope: co-created by Visa and Cloudflare, released on 14 October 2025 in the Visa Developer Center and GitHub, with feedback from Adyen, Ant International, Checkout.com, Coinbase, CyberSource, Elavon, Fiserv, Microsoft, Nuvei, Shopify, Stripe and Worldpay. By 2026 it is in live transactions: Visa Intelligent Commerce went live in Europe with 30+ issuers and merchants such as lastminute.com, and BILL with Billtrust ran a live B2B invoice-payment pilot using TAP.
Open: TAP is not an on-chain protocol and does not define refund or dispute liability; merchants must add signature verification and a directory, while agents must register and be recognised by issuers/networks; cross-network interoperability still leans on Web Bot Auth and coverage is expanding.

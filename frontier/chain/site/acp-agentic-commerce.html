支付与结算Payments & settlement

ACP：让 AI Agent 走完商家结账ACP: agent-ready merchant checkout

交集：ACP 不解决“模型怎么想”，而是把 Agent 购物拆成商家可实现的结账接口：商品 feed、购物车、结账会话、履约选项、委托支付、委托认证、订单与 webhook。商家仍是 merchant of record，可以按 agent/交易决定接不接单；支付凭据通过 payment handler 传递，不直接暴露卡号。
适用范围：官方定位为开放标准，Apache-2.0，REST 与 MCP 都可接；Stripe 的 Shared Payment Token 是首个兼容的委托支付实现，OpenAI 的 ChatGPT Instant Checkout 是首个落地场景。
未解决：规范仍是 beta，商家覆盖和地区有限；退款、争议、欺诈与合规责任仍在商家/PSP 侧；它不是 x402 那种按次 API 付费协议，两者解决不同层。The intersection: ACP does not decide how a model thinks; it turns agent shopping into merchant-implementable checkout interfaces — product feed, cart, checkout session, fulfillment options, delegated payment, delegated authentication, orders and webhooks. The merchant remains merchant of record and can accept or decline per agent or per transaction; payment credentials move through a payment handler without exposing the underlying card.
Scope: positioned as an open standard under Apache-2.0, with REST and MCP integration; Stripe’s Shared Payment Token is the first compatible delegated-payment implementation, and OpenAI’s ChatGPT Instant Checkout is the first live surface.
Open: the spec is beta with limited merchant and geographic coverage; refunds, disputes, fraud and compliance remain with merchants and PSPs; it is not x402-style per-call API billing — the two solve different layers.

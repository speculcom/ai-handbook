# 链 × AI · 内容规范

真相源：`entries.json`。本站**只做 AI 与链的交集**，不是加密资产站。

## 收录范围

| 收 | 不收 |
|---|---|
| 内容凭证与来源标识用于 AI 生成内容的协议文档 | 币价、行情、涨跌预测 |
| 模型与训练数据的溯源、许可与出处记录 | 交易所、钱包、投资建议 |
| 去中心化推理的官方协议说明 | 「哪个链更好」类横排或推荐 |
| 链上数据用于训练 / 评测时的授权与隐私问题 | 未公开白皮书的项目宣传稿 |
| EIP、官方规范、协议仓库 README | 社区二手解读 |

`nav` 的 `ext` 184 条延伸领域继续不上线；本站不把它们搬进来充数。

## 条目字段

| 字段 | 类型 | 要求 |
|---|---|---|
| `id` | 字符串 | 协议或概念短名，全站唯一 |
| `title` | `{zh, en}` | 双语，不写营销语 |
| `category` | 字符串 | `provenance` / `credential` / `inference` / `data-rights` / `protocol` 之一。`protocol` 装底层规范档案（EIP、W3C 规范、协议机制文档），与概念条目分工：概念条写「这件事是什么」，协议档案写「规范怎么规定」，不复制结论 |
| `url` | URL | 官方协议文档、EIP、白皮书或规范仓库 |
| `license` | 对象 | `kind` / `spdx`、`evidenceUrl`、`checkedAt`；官方规范用 `kind: official-specification` |
| `evidence` | 数组 | 每条含 `url` 与 `quote`，引官方原文；quote 必须真从抓到的页面里逐字摘出 |
| `notes` | `{zh, en}` | 三段，用 `\n` 分段：**交集**（与 AI 的交集具体在哪）/ **适用范围**（官方说了什么、没保证什么）/ **未解决**（还悬着的问题） |
| `verifiedAt` | 日期 | 实际核对日期 |
| `specs` | 对象 | 卡片规格表，键用「中文 / English」双语写法。**必含 `协议状态 / status`**，取值「已部署 / 草案 / 已废弃」，判断必须来自官方页面本身的措辞（例如 EIP 页头 Status 字段），不推断 |

## 口径

- 价格数字、收益率、市值一律不进档案。
- 许可与数据出处逐条挂；协议状态写明「已部署 / 草案 / 已废弃」并挂来源，不推断。
- 未知写「官方未说明」；受限链接不算死链（只有 404/410 才判死）。
- 协议与规范变动快，核验频率按月度；不改旧核验日来冒充复核。

新增条目走 `intake/<id>.json`，主流程合并进 `entries.json`。
